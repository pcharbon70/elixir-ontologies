## Implementation Overview

Phase 30.6 implements extraction for raise expressions which explicitly raise exceptions. Raise is a fundamental control flow mechanism for error handling in Elixir.

### What Was Implemented

1. **Ontology Updates** (`priv/ontologies/elixir-core.ttl`)
   - Added `hasMessage` property to RaiseExpression (links to message expression)
   - Added `refersToExceptionType` property (links to exception module)
   - Added `hasArgument` property for keyword arguments

2. **Expression Builder** (`lib/elixir_ontologies/builders/expression_builder.ex`)
   - Implemented `build_raise/3` - Main raise expression builder
   - Implemented `process_raise_args/3` - Handles all 4 raise variants
   - Implemented `process_raise_keywords/4` - Processes keyword arguments
   - Added raise case to `build_expression_triples/3` pattern matching
   - Raise expressions linked via RaiseExpression class type

3. **Unit Tests** (`test/elixir_ontologies/builders/expression_builder_test.exs`)
   - 5 comprehensive tests covering all raise expression scenarios
   - Test for raise with message only (RuntimeError default)
   - Test for raise with exception type only
   - Test for raise with exception and message
   - Test for raise with keyword arguments
   - Test for custom exception type references

## Technical Details

### Raise Expression Variants

```elixir
# 1. raise "message" -> raises RuntimeError with message
raise "error message"

# 2. raise Exception -> raises specific exception with default message
raise ArgumentError

# 3. raise Exception, "message" -> raises with custom message
raise ArgumentError, "invalid input"

# 4. raise Exception, [key: value] -> raises with attributes
raise ArgumentError, message: "custom message"
```

### AST Structure

```elixir
# raise "message"
{:raise, _, ["error message"]}

# raise Exception
{:raise, _, [{:__aliases__, _, [:ArgumentError]}]}

# raise Exception, "message"
{:raise, _, [{:__aliases__, _, [:ArgumentError]}, "message"]}

# raise Exception, [key: value]
{:raise, _, [{:__aliases__, _, [:ArgumentError]}, [message: "custom"]]}
```

### IRI Structure
- Raise expression: Generated by `fresh_iri/2` from context
- Message expression: `{raise_iri}/message`

## Key Implementation Notes

### Pattern Matching Order

A critical implementation detail is the order of pattern matching clauses. Since `{:__aliases__, _, _}` is a tuple, a guard like `is_tuple(arg)` will match it before more specific patterns. To handle this correctly:

1. **Most specific patterns first**: Module alias patterns must come before general tuple patterns
2. **Guarded patterns before unguarded**: The keyword args clause with `when is_list` guard must come before the general two-arg clause

```elixir
# Correct order (specific -> general):
defp process_raise_args([{:__aliases__, _, _}], ...), do: ...  # exception only
defp process_raise_args([{:__aliases__, _, _}, keyword_args], ...) when is_list(keyword_args), do: ...  # keywords
defp process_raise_args([{:__aliases__, _, _}, message_ast], ...), do: ...  # exception + message
defp process_raise_args([message_ast], ...) when is_binary(message_ast) or is_tuple(message_ast), do: ...  # message only
```

### Module IRI Creation

Exception type IRIs are created using the base IRI from context and the module name:

```elixir
exception_module_name = extract_module_name(alias_ast)  # "ArgumentError"
exception_module_iri = RDF.iri("#{context.base_iri}module/#{exception_module_name}")
```

For the default RuntimeError case (message-only raise), the IRI is:
```elixir
RDF.iri("#{context.base_iri}module/Elixir.RuntimeError")
```
