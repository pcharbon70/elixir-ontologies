## Problem Statement

Phase 30.7 implements extraction for throw expressions which throw values for non-local returns. Throw is used to exit a computation and return a value to a catch clause. Unlike raise (which is for exceptions), throw is for non-local returns within a process.

### Current State
- ThrowExpression class exists in ontology but lacks properties
- No extraction logic for throw expressions
- Throw expressions not captured in the expression graph

### Requirements
1. Add `hasThrownValue` property to ThrowExpression class in ontology
2. Extract throw expressions with any value
3. Link to the thrown value expression
4. Support all throw variants (literals, variables, complex expressions)

---

## Solution Overview

Implement throw expression extraction in ExpressionBuilder:

### Throw Expression Structure
- `throw :error` - Throws an atom literal
- `throw value` - Throws a variable
- `throw complex_expression()` - Throws result of expression

### IRI Structure
- Throw expression: Generated by `fresh_iri/2` from context
- Thrown value: `{throw_iri}/value`

### AST Pattern for Throw Expressions

```elixir
# throw with atom literal
{:throw, _, [:error]}

# throw with variable
{:throw, _, [{:x, [], nil}]}

# throw with complex expression
{:throw, _, [{:some_function, [], []}]}
```

### Throw Expression Examples

```elixir
# Simple throw with atom
throw :error

# Throw with variable
throw result

# Throw with function call
throw compute_value()

# Throw with tuple
throw {:error, reason}
```

## Notes and Considerations

### Throw vs Raise

| Aspect | Throw | Raise |
|--------|-------|-------|
| **Purpose** | Non-local returns | Exception handling |
| **Caught by** | catch clauses | rescue blocks |
| **Value type** | Any term | Exception struct |
| **Use case** | Early exit from nested computation | Error conditions |

### Throw Semantics

- `throw/1` is used for non-local returns within a process
- Values thrown can be any Elixir term
- Must be caught by a catch clause in a try block
- If uncaught, the process exits with exit reason `:nocatch`

### AST Structure

- AST is always `{:throw, meta, [value_ast]}`
- The value can be any expression AST node
- We recursively extract the value using `build_expression_triples/3`

### Integration Point

- Throw expressions are control flow expressions
- They're detected in `build_expression_triples/3` pattern match
- They connect to catch clauses (already implemented in Phase 30.3)
