## Problem Statement

Phase 30.6 implements extraction for raise expressions which explicitly raise exceptions. Raise is a fundamental control flow mechanism for error handling in Elixir.

### Current State
- RaiseExpression class exists in ontology but lacks properties
- No extraction logic for raise expressions
- raise expressions not captured in the expression graph

### Requirements
1. Add properties to RaiseExpression class in ontology
2. Extract raise expressions with message only
3. Extract raise expressions with exception type
4. Extract raise expressions with keyword arguments
5. Link to exception types and message expressions
6. Support all raise variants

---

## Solution Overview

Implement raise expression extraction in ExpressionBuilder:

### Raise Expression Structure
- `raise "message"` - Raises RuntimeError with message
- `raise ExceptionType` - Raises specific exception
- `raise ExceptionType, "message"` - Raises specific exception with message
- `raise ExceptionType, attribute: value` - Raises with keyword arguments

### IRI Structure
- Raise expression: Generated by `fresh_iri/2` from context

### AST Pattern for Raise Expressions

```elixir
# raise with message only (raises RuntimeError)
{:raise, _, ["error message"]}

# raise with exception and message
{:raise, _, [{:__aliases__, _, [:ArgumentError]}, "error message"]}

# raise with exception only
{:raise, _, [{:__aliases__, _, [:RuntimeError]}]}

# raise with keyword arguments
{:raise, _, [{:__aliases__, _, [:ArgumentError]}, [message: "custom message"]]}
```

### Raise Expression Examples

```elixir
# Simple raise with message
raise "error message"

# Raise specific exception
raise ArgumentError

# Raise with exception and message
raise ArgumentError, "invalid input"

# Raise with keyword arguments
raise ArgumentError, message: "custom message"
```

## Notes and Considerations

### Raise Variants

1. **raise "message"** - Equivalent to `raise RuntimeError, message: "message"`
   - Default exception: RuntimeError
   - Message becomes the `:message` attribute

2. **raise ExceptionType** - Raises exception with no attributes
   - Exception must be a module implementing the Exception behaviour

3. **raise ExceptionType, "message"** - Raises with message attribute
   - Message becomes the `:message` attribute

4. **raise ExceptionType, attribute: value** - Raises with custom attributes
   - Can set any attributes defined on the exception struct

### AST Structure Notes

- Message can be a string literal or any expression
- Exception type is an alias AST node: `{:__aliases__, _, [:Module]}`
- Keyword arguments are a keyword list: `[key: value, ...]`

### Integration Point

- Raise expressions are control flow expressions
- They're detected in `build_expression_triples/3` pattern match
- No special handling needed in try blocks (raise is just an expression)
